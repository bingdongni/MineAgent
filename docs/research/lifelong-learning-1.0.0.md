# v1.0.0：在真实模组里保持经验、迁移和协作

本版将 v0.6.0 的条件实验推进到固定版本的真实 Minecraft 模组环境。学习仍发生在外部经验、技能和计划中，不训练接入模型的权重。用户可以使用官方 API、中转或本地模型；下面的本地验证不需要密钥，也不调用付费模型。

## 实现的区别

同一条经过观察验证的条件经验，同时决定能否召回、能否生成技能、能否修复计划、能否作为队友的学习线索。历史记录、队友报告和缓存命中均不能替代当前游戏观察。工程上的贡献是把这些边界落实到执行与回归测试中；没有以此宣称算法首创、优于所有相关项目或已经实现 AGI。

| 目标 | v1.0.0 的具体变化 | 约束 |
| --- | --- | --- |
| 旧任务保持 | 最多 256 条活跃规则和 1,024 条历史规则；优先保留稀有机制，按目标召回、重新生成有条件的执行技能 | 有界存储会淘汰内容；不承诺无限记忆 |
| 长期记忆 | 最多 128 个任务、每个 64 个里程碑；保留起始锚点和近期证据，区分动作成功与目标验证 | 恢复后的进行中任务转为中断，不恢复旧执行器所有权 |
| 跨任务迁移 | 保持注册类型、环境指纹、实际输入、前态、维度、端口面与效果绑定；当前目标重新观察后才能执行 | 不会自动把两种不同模组机器视为等价 |
| 长程规划 | 修复前回温相关历史经验；先按目标和前置条件向后筛选算子，再应用 64 算子、128 搜索扩展、8 步上限 | 只建模已验证效果；可能消耗的输入被遗忘，不能凭搜索创造资源 |
| 陌生机器 | 读取真实公开端口；`inspect_gui` 可只读检查携带物品的槽位接收性、可用容量及公开布局 | 接受某物品不代表该槽位就是正确配方角色；仍需观察真实产出 |
| 反应与适应 | 小量公开端口动作同步返回真实移动量与新观察；本地执行及快速战术循环继续独立于模型 | 无公开接口是接口缺口；不把它解释成“配方错误” |
| 协作 | 带前驱关系的任务、200 tick 租约和公开端口资源互斥；新鲜事实验收与超时接管 | 这是同一主人伙伴间的本地协调，不是分布式共识或任意 NPC 协作 |
| 共同学习 | 已验证规则可以作为队友候选，接收方的支持数、上下文数归零且没有执行器；仍需两个本地独立验证 | 不允许反复分享覆盖已有反例或提升置信度；重载撤回已失效的分享 |
| 成本 | 稳定经验引用、严格检索预算；已知官方新模型的显式缓存边界落在耐久前缀上 | 保留原有中转、本地和其他厂商协议；没有额外预热请求，不保证实际缓存命中或账单收益 |

## 新的游戏工具用法

### 公开端口和陌生菜单

1. `inspect_block` 的 `capabilities=true` 可读取交互范围内的可见端口。可选 `face` 为 `up/down/north/south/east/west`，指定面必须真实可见。
2. `transfer_port` 的参数是 `x,y,z,direction,item_id,inventory_slot,amount`；`direction` 为 `into_block` 或 `from_block`，`amount` 为 1–64，携带槽位为 0–35。可选 `dimension` 和 `face` 用于绑定已观察目标。
3. 工具检查加载状态、交互距离、视线、世界交互权限和团队租约。Fabric 使用公开 Transfer API 事务，NeoForge 使用公开物品能力；返回 `moved_count`、`postcondition_verified` 和新公开观察。
4. 端口未开放时，先通过普通游戏交互打开菜单，再调用 `inspect_gui({"inventory_slot":0})`。返回正常菜单索引、玩家索引、`slot_type`、公开 `x/y`、`accepts_probe` 与 `probe_space`；检查本身不移动物品。不支持的槽位检查明确标为 unavailable。
5. 用 `transfer_items` 指向检查得到的菜单索引，重新读取输入、输出和玩家库存。菜单索引与原生库存索引不同；匿名槽位的 Java 类名也不能证明角色。

端口实验必须声明完全相反的 `transfer_port` 补偿：同一坐标、物品、数量和携带槽位，方向相反。学习器自动绑定维度、观察面与携带输入条件。声明可逆并不保证第三方接口或世界变化后仍可恢复；实际补偿结果单独记录，不把失败藏掉。

### 召回与计划恢复

- `explore_mechanism` 的 `mode=recall, query=...` 返回相关冷存储规则和有预算的任务时间线。此操作只读。
- `mode=activate, rule_id=...` 回温当前环境里仍有效的已验证规则，生成有条件的适配技能；失效、反例、旧环境经验不会因此重新获得执行权限。
- `mode=transfer` 仍需当前目标类型、维度和条件都被观察。不同端口面不会自动合并。
- `mode=repair` 在搜索前召回相关历史算子。已完成节点、其他分支和最终验收条件保留；方案不是成功证明，执行时会再次检查前置条件和效果。

任务时间线的总渲染预算最多 8,000 字符；默认经验引用为规则和任务历史共同分配不超过 5,600 字符。回读不增加支持次数，也不重写证据时间戳。

### 团队任务与经验

`coordinate_team` 保留 `status/commit/request_support/clear`，增加以下操作：

| action | 参数与行为 |
| --- | --- |
| `post_job` | `job_id,objective,resource,dependencies,acceptance`；前驱必须已经存在，条件列表不可被同 ID 覆盖 |
| `claim_job` | `job_id`；前驱均已验证且工作者、资源空闲时获得 200 tick 租约 |
| `complete_job` | `job_id`；只有持有者能提交，验收条件必须由本地新鲜事实匹配，且观察时间不早于认领 |
| `share_experience` | `rule_id`；只发布自己的当前有效规则，分享有效期 24,000 tick |
| `team_experiences` | 可选 `query`；返回至多 4 条相关队友历史线索 |
| `adopt_experience` | `rule_id`；建立零本地支持的候选，不能覆盖既有本地经验 |

`dependencies` 是 ID 的 JSON 数组；`acceptance` 是条件 JSON 数组（也可字符串编码），条件字段为 `subject,predicate,value,comparison,minimum_confidence`。资源按观察工具提供的完整主体填写，例如 `block:minecraft:overworld:10,64,20`。公开端口写入会遵守该资源的同主人租约；其他自定义工具需要自行接入协调检查。活跃执行续租，闲置会过期；死亡、销毁和世界关闭回收本地共享状态。任务完成并不保证资源永远保持完成时状态，后继动作仍必须重新观察。

## 可复现的真实模组环境

锁文件是 [modpack-lock.json](../../fabric/src/modtest/resources/modpack-lock.json)。下载器只获取锁定的作者发布文件，验证 SHA-512，并从已校验的父 JAR 提取声明的内嵌依赖，保存完整来源链。模组只作为隔离的测试运行依赖，不复制进 MineAgent 发行包。

| 组合 | 固定真实依赖 | 覆盖内容 |
| --- | --- | --- |
| storage | Extended Drawers 3.0.4+mc.1.21.1 | 两台真实抽屉学习与反向补偿；A→B→A 和 JSON/运行时恢复；新目标和错误面的迁移边界 |
| industry | Tech Reborn / RebornCore 5.11.19 | 未配置端口拒绝、正常菜单回退、真实冶炼、真实电能容量与 API 单位 |
| combined | 上述模组 + Farmer's Delight Refabricated 1.21.1-3.2.8 | 真实加热烹饪、模组物品跨模组搬运、双伙伴任务依赖和资源互斥 |

这是自选的固定组合环境，不是已经测完所有公开大型整合包。选择 FD 3.2.8 是为了匹配 Minecraft 1.21.1 的开发工具链；没有把未经验证的新版本写为已支持。Fabric API 固定到 0.116.17+1.21.1，补齐旧开发依赖缺少的约定标签；不通过修改第三方 JAR 或私有规则来掩盖问题。

```powershell
py -3 scripts/provision-modpack-tests.py --profile combined
.\gradlew.bat --no-daemon -Pmodpack_profile=combined :fabric:test :fabric:verifyModpackGameTests
```

`storage` 和 `industry` 使用相同命令切换 profile。测试世界、下载依赖和 XML 均位于 `fabric/build`。测试暂停模型规划轮次，但调用真实服务器中的生产观察、物品移动、经验学习、适配技能及协作模块；它们是工程验证，不是模型自主发现方案的成功率评测。

## 模型缓存协议

沿用 v0.6.0 对未上报缓存与显式零的区分，并保存读、写 token 和覆盖率。对于官方 HTTPS OpenAI 端点与已知 GPT-5.6 / GPT-6 家族，完整请求可在已声明的耐久消息边界写入显式缓存断点，使用 30 分钟 TTL；Chat 和 Responses 使用各自的内容块格式。动态世界尾部不写缓存断点。Responses 增量链不强行改为完整缓存请求。未知中转、本地端点和其他模型沿用原协议，不凭厂商别名添加私有字段。

这些策略的依据是 [OpenAI Prompt caching 文档](https://developers.openai.com/api/docs/guides/prompt-caching)。缓存有写入费用及服务端容量、寿命等条件；本轮没有真实模型调用，因此只验证请求结构和计量逻辑，不给出虚构命中率或人民币节省。

## 研究借鉴与自己的实现

| 一手来源 | 借鉴点 | 本项目的实现与边界 |
| --- | --- | --- |
| [Voyager](https://voyager.minedojo.org/) | 成功技能的可复用积累 | 保留声明式技能；额外将证据有效性绑定当前身份、端口面、维度、输入与反例，限制执行权限 |
| [A-MEM](https://arxiv.org/abs/2502.12110) | 相连的长期记忆与检索 | 本版实现有界规则档案和任务锚点；未照搬其全套链接更新算法 |
| [All-Mem](https://arxiv.org/abs/2603.19595) | 非破坏证据、预算内暴露有用信息 | 历史与活跃规则分离，回温不产生新证据；否定状态同步保留，避免冷存储复活失效技能 |
| [FlexA-Mem](https://arxiv.org/abs/2610.33274) | 任务时间线、精确证据和预算渲染 | 固定锚点与里程碑检索，不为整理记忆额外调用模型；所有渲染预算可测试 |
| [Tech Reborn](https://github.com/TechReborn/TechReborn)、[Team Reborn Energy](https://github.com/TechReborn/Energy)、[Extended Drawers](https://github.com/MattiDragon/ExtendedDrawers)、[FD Refabricated](https://github.com/MehVahdJukaar/FarmersDelightRefabricated) | 真实公开接口、不同菜单和自动化限制 | 作者原始依赖固定版本运行；Agent 只看普通观察和公共端口，不读取测试答案或任意私有 NBT |

上述论文和开源项目用于设计参考；没有复现它们的完整评测，不能据此把本项目数值与其论文表格直接比较。具体实测与尚未证明的能力见 [v1.0.0 验证记录](validation-1.0.0.md)。

## 兼容与迁移

记忆外层格式升级到 15；旧格式按原有兼容逻辑读取，新增档案和任务时间线缺失时为空。旧条件版本不足的支持证据仍会降级，不借版本升级给旧规则补造条件。环境指纹包含模组版本，升级 MineAgent 或其他模组可能使旧技能进入待重验状态。重载会同时撤销活跃与冷存储规则；完整恢复前仍需当前环境验证。

正式支持 Minecraft 1.21.1 / Java 21 / Fabric；NeoForge 仍为实验性支持，其构建通过不能替代同一真实模组集的原生运行测试。未证明所有模组、公开整合包、多天持续游戏、模型未知任务通关率和任意第三方能力实现都可靠。AGI 是研究方向，不是本版验收结论。
